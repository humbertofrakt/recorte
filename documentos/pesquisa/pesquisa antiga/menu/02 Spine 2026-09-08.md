# Spine (Esoteric Software) — como a interface é organizada

Editor Spine 4.x. Fonte: guia oficial do usuário e cheat sheet.
Pesquisa feita em 08/09/2026.

---

## O que dá para aprender com o Spine

1. O menu principal é **um botão só**: o logo Spine no canto. Tudo entra por ali.
2. A tela tem duas metades: **viewport** à esquerda, **árvore (Tree)** à direita.
3. Um **único ícone** troca o programa inteiro entre **Setup** e **Animate**.
4. Cada painel é uma **aba** que se arrasta, encaixa, minimiza e fecha.
5. Ferramenta tem **letra única**: C, V, X, Z, B, N, G. Sem combinação.

---

## 1. Barra de menus e barra de ferramentas

### 1.1 O menu Spine (o logo no canto)

Não existe barra de menus tradicional (Arquivo / Editar / Exibir).
Existe **um logo Spine** clicável no canto. Ele abre o menu principal.

Atalho: `alt+F` (Mac: `opt+F`).

O que o menu contém, segundo o guia:

|        Grupo         |            Para que serve             |
|:--------------------:|:-------------------------------------:|
|   Abrir / Salvar     |      abrir e salvar projetos          |
| Importar / Exportar  |    trazer e mandar dados para fora    |
|      Settings        |      todas as configurações           |

### 1.2 Botões ao lado do logo (titlebar)

|      Botão      |               Comportamento                |         Atalho          |
|:---------------:|:------------------------------------------:|:-----------------------:|
|     Open        | clique abre; **arrastar** mostra recentes  |       `ctrl+O`          |
|     Save        |  `shift` = "salvar como"                   |       `ctrl+S`          |
|     Undo        |            desfaz                          |       `ctrl+Z`          |
|     Redo        |            refaz                           | `ctrl+shift+Z` ou `ctrl+Y` |
| Welcome screen  | ícone de envelope; muda quando há notícia  |     não confirmado      |

Detalhe bom: o botão Open **arrastado** vira lista de recentes.
Segurar `shift` nele abre a janela de arquivos do sistema.

### 1.3 A barra de ferramentas (toolbar)

O guia diz: "a barra de ferramentas principal fica **embaixo do viewport**".
É uma **fileira horizontal de botões**.

Nas Settings existe a opção de **mudar a posição da toolbar** e de
**mostrar ou esconder o texto** dos botões. Ou seja: ícone, texto, ou os dois.

Ferramentas na toolbar (detalhe na seção 8):
Rotate, Translate, Scale, Shear, Pose, Create, Weights.

A toolbar também traz **campos numéricos** (X, Y, rotação, escala) e, ao lado
de cada campo, um **botão de chave** que grava o valor na animação.

### 1.4 O botão Setup / Animate

É **um ícone no canto superior esquerdo do viewport**. Clicou, trocou.

|   Modo   |                Para que serve                 |
|:--------:|:---------------------------------------------:|
|  Setup   | montar o esqueleto, pose de repouso, anexos   |
| Animate  |      criar as animações sobre esse setup      |

Cada modo tem **seu próprio conjunto de painéis** disponíveis.
A caixa "Views" mostra listas diferentes em Setup e em Animate.

## 2. Layout da tela e os painéis

### 2.1 Layout padrão

|      Região        |            O que fica ali             |
|:------------------:|:-------------------------------------:|
|     Esquerda       |        Viewport (a cena)              |
|      Direita       |          Tree (a árvore)              |
| Embaixo (Animate)  | Graph, com Dopesheet em aba ao lado   |

Em Setup mode a tela é basicamente viewport + tree.
Ao entrar em Animate, aparecem Graph e Dopesheet na faixa de baixo.

O guia **não informa a porcentagem exata** de tela de cada painel. Não confirmado.

### 2.2 A caixa "Views"

Fica no **canto superior direito** da janela do Spine.
É um *select box*: você escolhe o painel e ele abre.

Painéis já abertos aparecem **acinzentados**, mas ainda clicáveis — clicar
apenas traz o foco para eles.

### 2.3 Abas: mover, encaixar, redimensionar

|      Ação       |                    Como se faz                     |
|:---------------:|:--------------------------------------------------:|
|     Mover       | arrastar a **aba**; um retângulo laranja mostra onde cai |
|     Agrupar     |      soltar uma aba em cima de outra               |
| Redimensionar   |          arrastar a **borda** do painel            |
|    Minimizar    | ícone de menu ao lado da aba → Minimize            |
| Minimizar tudo  |                     **F9**                         |
|     Fechar      | ícone de menu → Close, ou duplo clique no ícone    |
|     Reabrir     |           pela caixa **Views**                     |

Painel minimizado vira **ícone ao lado da caixa Views**. Clicou, volta.

**Limitação importante:** o Spine **não** deixa destacar um painel como
janela flutuante para outro monitor. O jeito é esticar a janela do Spine
sobre os dois monitores.

### 2.4 Os painéis principais

|      Painel      |                  O que faz                       |
|:----------------:|:------------------------------------------------:|
|      Tree        |     árvore do projeto inteiro (seção 7)          |
|    Dopesheet     |     tempos das chaves (seção 5)                  |
|      Graph       |     curvas de valor no tempo (seção 5)           |
|     Timeline     |  só a régua de tempo, para ficar perto do trabalho |
|     Playback     |  FPS, velocidade, stepped/interpolated (seção 4) |
|     Preview      |  toca a animação como o runtime toca (seção 4.4) |
|     Weights      |  pesos de ossos sobre vértices de mesh           |
|     Metrics      |  contagem de ossos, vértices, triângulos, área   |
|    Animations    |  lista de animações do esqueleto                 |
|      Audio       |  som na linha do tempo                           |
|    Ghosting      |  "fantasmas" dos quadros vizinhos (onion skin)   |
|     Outline      |  contorno dos anexos                             |
|   Mesh Tools     |  ferramentas de malha                            |
|   Slot Color     |  cor por slot                                    |
|      Skins       |  troca de peles                                  |

O painel **Weights** tem: botão **Bind**, lista de ossos com cor, e as
visualizações **Pies**, **Overlay** e **Selected**.
A ferramenta Weights tem modo **Direct** e três pincéis: **Add**, **Remove**,
**Replace**, cada um com **Strength**, **Size** e **Feather**.
Botões automáticos: **Auto**, **Smooth**, **Prune**, **Weld**.

O painel **Metrics** conta ossos, constraints, slots, anexos totais e visíveis,
vértices, triângulos, transformações de vértice, área (fill rate) e timelines.
Serve para achar gargalo de desempenho.

## 3. Controles do viewport

### 3.1 Pan e zoom

|    Ação    |                    Como                          |
|:----------:|:------------------------------------------------:|
|    Pan     | botão **direito** + arrastar                     |
|  Pan (2)   | segurar **J** + botão esquerdo arrastando        |
|   Zoom     | **roda do mouse**                                |
|  Zoom (2)  | `ctrl` (`cmd`) + botão direito arrastando        |
|  Zoom (3)  | segurar **U** + botão esquerdo arrastando        |

Repare: o Spine usa **teclas seguradas** (J, U) como modificador de arraste.
Não usa a barra de espaço para pan.

### 3.2 Enquadrar

Dois botões no **canto inferior esquerdo** do viewport:

|      Botão       |          O que faz          |        Atalho          |
|:----------------:|:---------------------------:|:----------------------:|
|  Lupa            |        zoom para 100%       | `ctrl+F` / `cmd+F`     |
|  Caixa           | enquadra o esqueleto inteiro | `ctrl+shift+F`        |

### 3.3 Opções de exibição

Existe um **painel de opções do viewport** organizado em **colunas**:

|   Coluna    |                O que controla                 |
|:-----------:|:---------------------------------------------:|
|   Seleção   | se ossos / regiões / meshes podem ser clicados |
| Visibilidade|      se aparecem ou não na cena               |
|    Nomes    |       se mostra a etiqueta com o nome         |

As linhas são os tipos: **bones**, **region e mesh attachments**, e os
demais anexos.

Ou seja: o mesmo item tem três chaves separadas — ver, selecionar, nomear.
Isso é o truque mais copiável do Spine. Você pode ver um osso sem poder
clicar nele por engano.

### 3.4 Grade e fundo

Nas **Settings → Viewport** há:

|         Opção          |               O que faz                |
|:----------------------:|:--------------------------------------:|
|  Background colors     |    cor e padrão do fundo               |
|     Pixel grid         | simula pixel art rasterizando a cena   |
|      Smoothing         | 11 níveis, inclui bicúbico             |
|     Anti-aliasing      |       suavizar bordas                  |
|      Bone scaling      |     tamanho visual dos ossos           |
| Highlight de anexos    |       realce ao selecionar             |

Uma **grade métrica clássica com eixos X/Y nomeados** não aparece descrita no
guia. O que existe é o **pixel grid**. Eixos e origem: **não confirmado**.

## 4. Playback — tocar a animação

Aqui há uma separação que vale copiar: **os botões de tocar não estão no
painel Playback**. Estão como **atalhos de teclado do modo Animate** e na
régua de tempo. O painel Playback guarda só os **ajustes**.

### 4.1 Botões de reprodução (modo Animate)

|         Ação          |     Tecla      |
|:---------------------:|:--------------:|
|  Tocar para frente / parar |    **D**   |
|  Tocar para trás / parar   |    **A**   |
|   Ir para o início         |    **Q**   |
|   Ir para a última chave   |    **E**   |
|      Chave seguinte        |    **W**   |
|      Chave anterior        |    **S**   |
|      Quadro seguinte       |    **R**   |
|   Avançar 10 quadros       | **shift+R**|
|      Quadro anterior       |    **F**   |
|   Voltar 10 quadros        | **shift+F**|
| **Ligar/desligar o loop**  | **ctrl+R** |

Note o desenho: **D e A** são tocar; **Q e E** são as pontas; **W e S** são
chave a chave; **R e F** são quadro a quadro. Tudo na mão esquerda, ao lado
do WASD. A mão direita fica no mouse o tempo todo.

### 4.2 Loop (repetir) x tocar uma vez

O loop é um **estado ligado/desligado**, não um botão separado de "tocar em
loop". Liga com `ctrl+R`.

Com o repeat ligado, o comportamento vale **também para o arraste manual**:
se você arrasta a régua além do último quadro, a posição **volta para o
primeiro quadro** — mas só se o arraste tiver começado antes do último quadro.
Isso deixa você "esfregar" uma animação cíclica sem parar na ponta.

Marcadores de **loop start / loop end** separados: **não confirmado** no guia.
O loop do editor usa o intervalo da própria animação.

### 4.3 A barra de progresso (Timeline)

A régua de tempo aparece no Graph, no Dopesheet, no Audio e no painel
**Timeline** (que existe só para colocar a régua perto do seu trabalho).

|         Ação           |             Como              |
|:----------------------:|:-----------------------------:|
|  Arrastar o cursor     |    botão esquerdo arrastando  |
| Arrastar sem travar no quadro | `shift` + arrastar     |
|    Zoom da régua       |        roda do mouse          |
|    Pan da régua        |  botão direito arrastando     |
| Enquadrar todas as chaves |    botão **Zoom Keys**     |

Campo numérico do quadro atual: **não confirmado** no guia.

### 4.4 O painel Playback (os ajustes)

|      Controle       |                 O que faz                     |
|:-------------------:|:---------------------------------------------:|
|   **Timeline FPS**  | quadros por segundo da régua. Padrão **30**    |
|     **Speed**       | velocidade da reprodução, com botões de % fixa |
|    **Stepped**      | sem interpolação nenhuma entre chaves          |
|  **Interpolated**   | desligado = arredonda para o quadro inteiro    |

Atalho para abrir: `alt+P` no modo Animate.

Dois avisos do guia:
Mudar o FPS **muda a velocidade real** da animação, no editor e no jogo.
Escolha o FPS **antes** de animar.
A velocidade (Speed) **não é salva, não é exportada e não existe no runtime**.
É só para você conferir o trabalho devagar.

### 4.5 Preview — tocar como o jogo toca

O painel **Preview** simula o runtime. Panorâmica e zoom funcionam igual ao
viewport.

|      Controle      |                   O que faz                    |
|:------------------:|:----------------------------------------------:|
|   Lista de animações | canto superior direito; clique põe na track  |
|      **Speed**     |         velocidade, padrão 100%                |
|      **Mix**       |     tempo de transição entre animações         |
|     **Repeat**     |    se a **próxima** animação vai repetir       |
|     **Alpha**      |   mistura com as tracks de baixo (0 a 1)       |
|  **Hold Previous** |   evita o "afundamento" na transição           |
|    **Additive**    | soma à track de baixo em vez de substituir     |
|      Tracks        |      até **15** animações ao mesmo tempo       |

Pegadinha documentada: Repeat, Hold Previous e Additive valem para a
**próxima** animação, não para a que já está tocando.

## 5. Dopesheet e Graph — a linha do tempo

### 5.1 O que o Dopesheet mostra

Mostra e edita **só o tempo** das chaves. Muitas propriedades ao mesmo tempo.

Estrutura em três níveis:

|      Nível       |                  O que mostra                     |
|:----------------:|:-------------------------------------------------:|
| Linha de resumo  | nome da animação + **todas** as chaves de baixo   |
|  Linha de osso   |  chaves agrupadas pelo osso mais ligado à propriedade |
| Linha de propriedade | todas as chaves daquela propriedade           |

A **linha de resumo é a primeira**, no topo. Serve para mexer em todas as
chaves da animação de uma vez. É o equivalente ao "summary" pedido.

Detalhe fino: quando a linha do osso está **expandida**, ela só mostra chave
onde **várias propriedades caem no mesmo quadro**. Isso evita ruído visual.

### 5.2 Cores das chaves

Cada tipo de chave tem cor própria.
**Chave branca = vários tipos de chave no mesmo quadro.**

As **linhas entre as chaves** indicam o tipo de interpolação. Você lê a curva
sem sair do dopesheet.

### 5.3 Navegar e editar chaves

|         Ação            |               Como               |
|:-----------------------:|:--------------------------------:|
|   Chave anterior/seguinte |          **S** / **W**         |
|   Selecionar uma chave  |          clique                  |
|  Somar à seleção        |     `ctrl` + clique              |
|    Seleção por caixa    | arrastar em espaço vazio         |
|    Mover no tempo       | arrastar para esquerda/direita   |
|   Mover sem travar      |  `shift` + arrastar              |
|      Duplicar           | `ctrl+shift` ao começar o arraste |
|  Mover junto com as seguintes | `alt` + arrastar           |
| Deslocar em ciclo (loop) | `ctrl+alt` + arrastar           |
|   Esticar a seleção     | arrastar a **borda** da seleção  |
|       Apagar            | `Delete` ou **duplo clique**     |
|  Recortar / copiar / colar | `ctrl+X` / `ctrl+C` / `ctrl+V` |

O `ctrl+alt` para "dar a volta" nas chaves é feito para animação cíclica:
o que sai pela direita entra pela esquerda.

### 5.4 Zoom da timeline

Roda do mouse na régua = zoom.
Roda do mouse **dentro** do dopesheet/graph = rolar para cima e para baixo.
Botão **Zoom Keys** enquadra todas as chaves.

### 5.5 Locked x Unlocked

|    Modo    |                  Comportamento                    |
|:----------:|:-------------------------------------------------:|
| Unlocked   | mostra as linhas conforme o que está selecionado  |
|  Locked    | mantém as linhas mesmo mudando a seleção          |

Unlocked é bom para focar um osso. Locked é bom para trabalhar com vários.

### 5.6 Como o Graph se relaciona

O Graph mostra **valor no eixo Y e tempo no eixo X**. Vira curva.
O Dopesheet mostra só tempo, mas mostra muito mais propriedades juntas.

**Seleção é compartilhada nos dois sentidos:** selecionou chave no dopesheet,
ela fica selecionada no graph, e vice-versa.

Com a sincronia ligada, o **dopesheet mostra as linhas das curvas visíveis no
graph**.

|       Controle do Graph      |                O que faz                  |
|:----------------------------:|:-----------------------------------------:|
|      Chaves = quadradinhos   |  X = quadro, Y = valor                    |
|        **Frame**             |  enquadra todas as curvas                 |
|      **Auto zoom**           |  ajusta sozinho para manter curvas à vista |
|      Alças de Bézier         |  duas alças arrastáveis por curva         |
|   `alt` + arrastar alça      |  separa as duas alças                     |
|  `shift` + arrastar alça     |  muda só o comprimento                    |

## 6. Points, Bounding boxes e o "pivot"

### 6.1 Point attachment — o pivot do Spine

Um **point attachment** é "um ponto no espaço **com uma rotação**".
É a resposta do Spine ao problema de "onde nasce a bala e para onde ela aponta".

Diferença para um osso:

|                | Osso (Bone) | Point attachment |
|:--------------:|:-----------:|:----------------:|
|    Posição     |     sim     |       sim        |
|    Rotação     |     sim     |       sim        |
| Escala / shear |     sim     |      **não**     |
|  Custo de CPU  |    maior    |     **menor**    |
| Pode ser escondido/mostrado | não do mesmo jeito | **sim** |
|  Entra em skin |     não     |     **sim**      |

É essa a razão de existir: mais barato que osso, e **pode viver dentro de uma
skin**. Armas diferentes = pontos de tiro diferentes, sem mexer no esqueleto.

### 6.2 Como criar o ponto na ponta da arma

1. Selecione **o osso da arma** (ou o slot da arma) na Tree.
2. No painel de propriedades da Tree, clique **`New...`** → **`Point`**.
3. Posicione o ponto na boca do cano.
4. **Gire o ponto** para apontar na direção do tiro. A rotação é metade do valor.
5. Se houver várias armas, crie um ponto por skin, com o mesmo nome.

Vários point attachments podem conviver **no mesmo slot**. O jogo escolhe qual
usar em tempo de execução.

**Limitação importante:** a posição e a rotação do point **não podem ser
animadas diretamente** com chaves. Quem se anima é o **osso pai**. O ponto
segue junto. Na prática isso basta: o cano da arma se move porque o braço se move.

### 6.3 Como o runtime lê isso

A classe é **`PointAttachment`**. Ela tem dois métodos:

|              Método                  |            Devolve            |
|:------------------------------------:|:-----------------------------:|
| `computeWorldPosition(bone, vector)` | posição no espaço do esqueleto |
|     `computeWorldRotation(bone)`     |   rotação em graus            |

Você passa **o osso ao qual o attachment está preso**. O resultado vem em
coordenadas relativas à **origem do esqueleto** — depois você aplica a
transformação do objeto do jogo (no Unity, o transform do GameObject).

Exemplo do runtime spine-unity:
`attachment.ComputeWorldPosition(bone, out x, out y)` e então converter para
o espaço do mundo com o transform do GameObject do esqueleto.

Receita para spawn de bala:

1. Achar o slot pelo nome.
2. Pegar o attachment do slot e converter para `PointAttachment`.
3. `computeWorldPosition(slot.bone, vec)` → onde nasce.
4. `computeWorldRotation(slot.bone)` → para onde aponta.
5. Instanciar a bala com essa posição e esse ângulo.

O guia do editor **não cita esses métodos**; eles vêm da documentação de
runtime e do código dos runtimes. Os nomes acima estão confirmados nos
runtimes; o texto exato do guia do editor sobre a API: não confirmado.

### 6.4 Bounding boxes

Um **bounding box attachment** é "um polígono usado em tempo de execução para
detecção de colisão, criar corpos de física, gerar efeitos de partícula e mais".

Apesar do nome, **não é retângulo**: é polígono livre.

Criar: selecione osso ou slot na Tree → **`New...`** → **`Bounding Box`**.
O Spine já entra em **modo de edição** com **new vertices mode** ligado.

|      Ferramenta       |                     O que faz                       |
|:---------------------:|:---------------------------------------------------:|
|   **Create**          | clicar na aresta adiciona vértice; duplo clique remove |
|   **Delete**          | clicar remove vértice; `ctrl` ou caixa para vários  |
| **New vertices mode** | redesenha o polígono do zero; fecha clicando no 1º vértice |

Fora do modo de edição, valem as ferramentas normais de rotate/scale/translate,
no polígono inteiro ou em vértices soltos. **O centro de rotação/escala pode
ser arrastado** pela mira central — isso é o pivot móvel.

Vértices de bounding box podem receber **deform keys**, mas o guia recomenda
usar **pesos (weights)** para que o polígono acompanhe os ossos sozinho.

## 7. Tree — a árvore

A Tree é o **índice do projeto inteiro**, à direita da tela.

### 7.1 O que ela organiza

|      Nó       |                 Conteúdo                    |
|:-------------:|:-------------------------------------------:|
|   Skeleton    |         o esqueleto e seus dados            |
|    Images     | pasta de PNG/JPEG; laranja = não usada, verde = usada |
|     Bones     |     hierarquia de ossos                     |
|     Slots     |  ranhuras, com os anexos dentro             |
|  Attachments  | region, mesh, path, bounding box, point, clipping |
|  Constraints  |     IK, path, transform, physics            |
|     Skins     |       conjuntos de anexos                   |
|  Animations   |     as animações do esqueleto               |
|    Events     |         eventos disparáveis                 |

Existe a opção **"Show slot folders under bones"**: as pastas de slot aparecem
debaixo do osso pai.

### 7.2 Manejo da árvore

|             Ação              |                 Como                    |
|:-----------------------------:|:---------------------------------------:|
|      Expandir / recolher      | clicar à **esquerda** do ícone          |
| Expandir com todos os filhos  | **botão direito** no nó                 |
| Expandir/recolher tudo        | duplo clique nos botões do topo         |
|          Selecionar           | clicar à **direita** do ícone           |
|      Somar à seleção          | `ctrl`+clique                           |
|      Selecionar faixa         | `shift`+clique                          |
|    Histórico de seleção       | **Page Up / Page Down**                 |
|    Mostrar / esconder         | **bolinha** na borda esquerda           |
| Esconder o galho inteiro      | botão direito na bolinha                |
|          Renomear             | **F2** ou duplo clique                  |
|         Reparentar            | arrastar o nó para o novo pai           |
|   Prévia da imagem            | passar o mouse; **F1** mostra na hora   |

Na borda **direita** aparecem **anotações**: dizem a que skin o item pertence,
que constraints agem sobre ele, e assim por diante.

Em modo Animate, cada nó ganha um **botão de chave** para keyframar dali mesmo.

### 7.3 Busca e filtros

Caixa de busca com curinga: `*` = qualquer trecho, `?` = um caractere.
Texto entre `/barras/` é tratado como **expressão regular**.

Botões de filtro rápido: só **bones**, só **slots**, só **attachments**.
Filtro ativo deixa o botão **vermelho** — você não esquece que filtrou.

Existe um diálogo **Find and Replace** com escopo: `Entire project`,
`Tree selection`, `Current skin`, `Selected skeletons`.

### 7.4 O painel de propriedades e o botão `New...`

**Embaixo da Tree** fica o painel de propriedades do item selecionado.
Ali há os botões de **duplicar**, **renomear** e **apagar**.

E ali está o botão **`New...`**. Ele cria o que couber no item selecionado:

|   `New...`    |            Cria             |
|:-------------:|:---------------------------:|
|    Point      |    point attachment         |
| Bounding Box  |   polígono de colisão       |
|    Region     |    anexo de imagem          |
|     Mesh      |    malha deformável         |
|     Path      |     caminho                 |
|   Clipping    |    máscara de recorte       |
|     Skin      |         pele                |
|   Animation   |       animação              |
|    Event      |        evento               |
|  Constraints  | IK, path, transform, physics |

A lista completa varia com o que está selecionado. O padrão é sempre o mesmo:
**selecione o pai, clique `New...`, escolha o tipo**.

## 8. Atalhos de teclado

### 8.1 Ferramentas (letra única)

| Ferramenta |  Tecla  |                    O que faz                     |
|:----------:|:-------:|:------------------------------------------------:|
|   Shear    |  **Z**  |  inclina; muda o ângulo entre os eixos X e Y     |
|   Scale    |  **X**  |  redimensiona, uniforme ou não                   |
|   Rotate   |  **C**  |  gira em torno do pivot                          |
| Translate  |  **V**  |  move em X e Y                                   |
|    Pose    |  **B**  |  move **e** gira ao mesmo tempo                  |
|   Create   |  **N**  |  cria ossos (só em Setup mode)                   |
|  Weights   |  **G**  |  pinta influência de osso sobre vértices         |

Z X C V B N: **teclas vizinhas na fileira de baixo**. A mão esquerda não anda.

|          Modificador           |               Efeito                 |
|:------------------------------:|:------------------------------------:|
| **Botão direito no viewport**  | alterna com a **última** ferramenta  |
|         Setas do teclado       | empurrar (nudge) o item              |
|  `shift` no Rotate             | trava de 15 em 15 graus              |
|  `ctrl` no Create              | cria osso novo para as imagens selecionadas |
|  `alt` no Create               | redesenha o osso selecionado         |

O truque do **botão direito alternando duas ferramentas** é o mais esperto:
você fica indo e voltando entre girar e mover sem tirar a mão do mouse.

## 9. Elogios e críticas dos usuários

### 9.1 Elogios

| O que dizem |
|:---:|
| "interface simplificada e flexível" |
| "interface intuitiva e curva de aprendizado curta" |
| foco só em animação esquelética, sem inchaço |
| "ótima para construir animações" |
| Dopesheet dá controle fino de tempo |

### 9.2 Críticas

| O que dizem |
|:---:|
| "curva de aprendizado íngreme para quem é novo em ferramentas 2D" |
| muitos recursos assustam o iniciante |
| **não dá para soltar um painel em outro monitor** (limitação do próprio guia) |
| ferramentas de exibição espalhadas entre painel, toolbar e Settings |

O veredito é dividido: quem já animou acha intuitivo; quem nunca animou
acha íngreme. **O mesmo programa recebe os dois julgamentos.**

A limitação de janela flutuante é reconhecida pela própria Esoteric Software
no guia. É o defeito mais objetivo da organização de tela.

### 9.3 O que copiar e o que não copiar

|          Copiar             |                Por quê                    |
|:---------------------------:|:-----------------------------------------:|
| Letra única por ferramenta  |  Z X C V B N, mão parada                  |
| Botão direito alterna ferramenta | economiza um clique por troca        |
| Semáforo verde/laranja/vermelho na chave | leitura instantânea         |
| Três colunas: ver / selecionar / nomear | resolve o clique errado      |
| Linha de resumo no topo do dopesheet | visão geral sem rolar          |
|  D A Q E W S R F            | tudo na mão esquerda, perto do WASD       |
| `New...` no painel de propriedades | um botão só cria tudo              |
| Filtro ativo fica vermelho  | você não esquece que filtrou              |

|      Não copiar        |               Por quê                |
|:----------------------:|:------------------------------------:|
| Painel preso à janela  | quem tem dois monitores sofre        |
| Botões de tocar só no teclado | iniciante não descobre         |
| Ajustes de exibição em 3 lugares | Settings, painel e toolbar |
